## Translation System
- **Structure**: Screen-specific translations in `/src/screens/[section]/config/locales/[section].en.json`
- **Common translations**: Shared translations in `/src/config/locales/common.en.json`
- **Autogenerated files**: Files in `/public/` are autogenerated and should NOT be edited directly
- **Usage**: Components use `useI18Language` hook to access translations
- **Keys**: Use translation keys instead of hardcoded text (e.g., `'add_customer'` not `'Add Customer'`)
- **Form fields**: All form titles, labels, and options should reference translation keys
- **Missing keys**: When adding new UI text, always add corresponding translation keys to the appropriate locale file

### Translation Component Patterns (CRITICAL)
**Components use translation IDs, NOT labels:**
- `PageTitle`: Use `titleId="translation_key"` (NOT `title="text"`)
- `ButtonList` items: Use `id: "translation_key"` (NOT `label: "text"`)  
- `RadioSelector`: Use `title="translation_key"` with `items=[{label: "key"}]`
- `EmptyListMessage`: Use `id="translation_key"`
- `IconButton`: Use `tooltip={getI18Translation('key')}` for dynamic tooltips
- **Dynamic text**: Import `useI18Language` and use `getI18Translation('key')`
- **Material-UI components**: DatePicker, TextField labels can remain as plain text when they have many dynamic options (timezones, etc.)

## Loading States & UI Feedback
- **NEVER use plain text for loading states** (e.g., "Loading...", "Processing...")
- **ALWAYS use one of these approved loading patterns:**
  1. **Skeleton Loaders** - For structured content (lists, cards, forms)
     - Import: `import Skeleton from '@material-ui/lab/Skeleton';`
     - Use `variant="text"`, `variant="rect"`, or `variant="circle"`
     - Match the skeleton structure to actual content layout
  2. **Project Spinner** - For general loading states
     - Import: `import Spinner from 'components/outputs/Spinner';`
     - Use `<Spinner />` for full-screen loading
     - Use `<Spinner size={24} />` for inline loading
  3. **CircularProgress** - For buttons and small components
     - Import: `import CircularProgress from '@material-ui/core/CircularProgress';`
     - Use in buttons: `<CircularProgress size={16} />` (small) or `size={24}` (default)
- **Pattern Examples:**
  ```javascript
  // ✅ Good - Skeleton for structured content
  {loading ? (
    <Skeleton variant="rect" width="100%" height={60} />
  ) : (
    <BankAccountCard />
  )}
  
  // ✅ Good - Spinner for general loading
  {loading ? <Spinner /> : <ComponentContent />}
  
  // ❌ Bad - Plain text loading
  {loading ? <Text>Loading...</Text> : <Content />}
  ```

## Routing & Access Control

### Screen Registration Checklist
When adding new screens, update these locations:
1. **util/general.js:651-693** - Add to `reservedPages` array (prevents URL conflicts)
2. **contexts/BusinessContext.js:19-31** - Add to `businessScreens` if business-related
3. **components/app/PrivateRouter.js** - Add lazy import + `<Route>` component
4. **components/app/AppMenu.js:47-175** - Add menu item in `appMenuConfig`
5. **screens/index.js:123-137** - Add to `states` object if needed

### Key Access Control Files
- `src/components/app/AppRoutes.js` - Public vs private route decision
- `src/components/app/PrivateRouter.js` - Authentication guards & tier verification
- `src/components/app/AppMenu.js` - Service-based menu access control

### Access Control Layers
1. **Tier Verification**: `userTier >= requiredTier` (PrivateRouter.js:109)
2. **Role Checks**: `isAdmin()`, `isBusiness()` utilities (util/general.js)
3. **Service Gates**: Business features require specific service combinations
4. **Manager Groups**: `checkBusinessGroup()` validates business access (util/business.js)

### Route Guards
- **Bridge KYC/TOS**: Forces `/bridge-terms/` if not approved
- **Tier Redirect**: Sends unverified users to `/onboarding/`
- **Admin Bypass**: Admins skip tier requirements
- **Public Routes**: `/documentation/`, `/email/`, `/password/`, `/checkout/`, `/sep24/`

### Routing Logic

#### **PrivateRouter Priority Order**
PrivateRouter evaluates redirects in this specific order:
1. **Bridge Service KYC/TOS** → `/bridge-terms/`
2. **Tier Verification** → `/onboarding/`  
3. **Business Onboarding** → `/onboarding/`
4. **Additional Requirements** → `/onboarding/`

#### **Key Loading States**
Wait for these data states before routing decisions:
- `hasTierData` - User tier information loaded
- `businessLoading` - Business data loading state
- `documentsLoading` - User documents loading state
- `addressesLoading` - Address data loading state
